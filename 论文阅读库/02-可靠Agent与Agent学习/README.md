## 2. 看完地图后，选一条支线

| 子方向 | 推荐顺序 | 与你现有经历的联系 |
| --- | --- | --- |
| 验证、反馈与选择性修复 | A02/A04/A27对照 → A21评估器 → A20过程监督 → A12训练修复 → A24 ImageRSI | RISA反馈质量、局部保持与修复停止 |
| 经验、记忆与迁移 | A03 → A08 → A15 LifeBench → A19 ACE → A22 V2 → A23 MemCalib → A25 DolphinBench | 工具经验、长期多源信息与误用经验 |
| Agent参数学习与多轮RL | A10后训练 → A07 DPO → A09 PPO → A11 R1 → A12 SCoRe → A17 RAGEN → A16 AgentGym-RL | 从执行轨迹形成可靠训练信号 |
| Agent训练系统 | 先读上一分支核心概念 → A18 Agent Lightning → A26新版 | 将原有工具Agent接入训练与观察系统 |
| 任务环境与评测 | A13 tau → A05 tau2 → A14 SWE-bench → A08/A15/A25 | 学会区分模拟器、测试与现实任务成功 |

这些路线有交叉，不用全部读完再动手。如果你的问题是错误反馈带来破坏，先建立可执行对照；如果是经验不适用，先控制检索和上下文预算；确实需要参数学习时再投入RL。

## 3. 必须放在一起读的几组论文

### 自我纠错三角：A02、A04、A27

比较反馈来自哪里、任务是什么、预算是否相同、是否能独立验证。它们不应简单概括成“有的论文说有效，有的说无效”；不同假设会产生不同结论。

### 当次修复、跨任务记忆、参数更新

A02 Self-Refine、A03 Reflexion、A06 Retrospex、A12 SCoRe分别代表不同变化位置。画一张表：更新对象是什么，是否持久，下一任务是否使用，哪些数据参与训练。

### 能力分数与可信评价

A05 tau2、A14 SWE-bench、A21 judge论文和A25 DolphinBench帮助你检查：谁定义真值，工具/用户/测试是否可靠，成本是否完整，重复成功与至少一次成功是否混用。

## 4. 最新论文怎么用

- **A16 AgentGym-RL、A19 ACE：** 2026正式会议相关工作，分别看多轮参数训练和上下文经验更新，区分更新层次。
- **A22 LongMemEval-V2：** 看经验如何帮助定制环境中的任务，原始页面注明Work in Progress，先认真核查协议。
- **A23 MemCalib：** 2026年9月首发、10月修订。看记忆过度使用和使用不足是否能同时改善。
- **A24 ImageRSI：** 2026-10-23首发。与你RISA后续相邻，先看任务内修复、经验准入和judge更新具体做了什么。
- **A25 DolphinBench：** 看任务执行、成本与延迟是否共同评估。
- **A26 Agent Lightning v1：** 与原作比较新增机制，避免把框架版本更新本身等同于新学习算法。

近期预印本纳入是为了查重和发现问题，并不意味着已经被社区独立验证。本目录不对所有条目作统一的“顶会已录用”判断。

## 5. 阅读后该做的第一项实验

建立一个小型工具环境，例如模拟数据库查询和受限更新。任务应有明确最终状态检查器。比较单次执行、固定修复、同预算重试和简单回退。

记录初始错误被修好的比例、初始正确被改坏的比例、完整调用成本和失败轨迹。先核对20–50条开发轨迹，建立错误分类，再设计训练或记忆方法。正式结论需要未参与调参的数据与足够评价。

如果接续RISA，应先确认原数据、代码和指导可用；不要将图像总分上涨直接等同于目标完成与背景保持都改善。

## 6. 最少的阅读产出

- 一张Agent闭环图，注明模型、工具、环境与验证器的职责。
- 一张反馈修复对照表。
- 一张“上下文、记忆、策略参数”更新层次表。
- 一个能够独立检查成败的小环境。
- 一页假设：哪个失败机制值得研究，如何验证。
