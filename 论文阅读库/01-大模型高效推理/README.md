## 1. 第一轮顺序

| 顺序 | 编号与短名 | 读到什么程度 | 前置知识 | 读完的小任务 |
| --- | --- | --- | --- | --- |
| 1 | E01 Inference Survey | 看分类、系统流程与瓶颈；它是2024系统地图，非最新综述 | 基本LLM概念 | 画出prefill/decode与缓存、服务调度的位置 |
| 2 | E02 Transformer | 复习QKV、因果注意力、残差；已掌握可快读 | 线代、张量 | 写出主要张量形状，区分原文与decoder-only |
| 3 | E03 FlashAttention | 精读IO动机和分块，证明可后补 | 注意力、GPU内存层次 | 解释为什么减少访存可以提速 |
| 4 | E04 PagedAttention | 精读内存管理与负载设置 | KV cache、批处理 | 分清分页管理和丢token压缩 |
| 5 | E05 Speculative Decoding | 理解草稿、验证、接受校正与成本 | 自回归生成、采样 | 写出草稿成本与接受率的权衡 |
| 6 | E06 AWQ | 精读校准、误差与硬件实现关系 | 数值精度、线性层 | 比较质量、显存与延迟，不预设必然加速 |
| 7 | E07 STARS | 利用已有经历掌握到能解释关键取舍 | 循环模型、自动微分 | 分析稳定且错误的样本 |
| 8 | E08 Test-Time Compute | 看预算、难度和可部署策略 | 候选采样、验证 | 提出一个同预算对照 |

8篇构成一张方向地图，不代表每项都要深入做研究。你不必先学完所有系统知识，才开始STARS检查点分析。

## 2. 看完地图后，选一条支线

| 子方向 | 推荐顺序 | 当前不必急着做什么 |
| --- | --- | --- |
| 循环/隐式推理与计算分配：与你最直接 | E15 Ouro → E07 STARS → E08计算预算 → E23 RecurTrace → E24 TAPS → E25动态计算 → E22真实批处理；E26补机制分析 | 从零预训练，或直接把少循环当加速 |
| KV cache与长上下文：组内衔接强 | E09 GQA → E11 H2O → E12 SnapKV → E16 LAVa → E17 SmallKV → E21 VeriCache | 同时混合多个压缩器却无法归因 |
| 服务系统与GPU计算 | E03 → E04 → E13 SGLang → E14 FlashInfer → E20 Strata | 一开始就实现多机服务或高性能attention |
| 低比特量化 | E06 AWQ → E10 GPTQ → E19 TurboQuant；结合E09与KV基础 | 把权重量化与KV量化视作同一个问题 |
| 解码与模型协作 | E05 → E18 TrigReason → E21 VeriCache | 把触发路由和保持目标分布的推测解码混同 |

量化支线中，GPTQ/AWQ是权重压缩入口，TurboQuant关注向量及KV表示；请分别理解目标和误差。最新方法也需要检查相关工作与公平基线，避免照搬传播材料中的“无损”“数倍加速”。

## 3. 近期论文优先怎么看

- **E20 Strata：** 2026正式系统论文。看层次缓存解决的真实约束、系统实现与负载，而非只看最高加速数。
- **E21 VeriCache：** 看压缩草稿与完整缓存验证怎样组合，精确性及传输重叠各自依赖什么。
- **E22–E26：** 直接服务于你的Looped LM查新。依次比较“存历史”“调步长”“实际跳过计算”“并发执行”“内部行为诊断”。

C类中未正式发表的工作先读摘要、方法图和实验协议。若你的想法与之直接相邻，再精读全文、代码和附录，不先假设它已经解决所有问题。

## 4. 三组建议对照

1. **E03 FlashAttention vs E04 PagedAttention：** 一个重点是算子IO，一个重点是缓存管理与服务。两者都提速，但改进层次不同。
2. **E11/E12 vs E16/E17 vs E21：** 从重要性淘汰到动态预算、小模型补偿，再到验证；比较是否近似、如何保留真值、总资源成本。
3. **E07 vs E23/E24/E25：** 稳定性、循环记忆、步长控制、退出与KV实现分别改变什么；这组最有助于你辨认潜在课题重叠。

## 5. 阅读后该做的第一项实验

先选现有资源可运行的模型，固定数据、解码和硬件，改变输入/输出长度，建立质量、延迟、显存基线。然后只增加一个变量：量化、前缀复用或固定循环深度。

每个结果至少回答：质量是否保持，收益来自哪些条件，辅助计算花了多少，离线微基准能否说明真实请求表现。若代码不可得或环境无法复现，阅读机制仍有价值，但不要写成已完成复现。

## 6. 最少的阅读产出

- 一张领域地图。
- E03/E04/E05各一页机制与瓶颈解释。
- 选一个分支，做3–5篇方法对照表。
- 一份可复现的基线报告。
- 一页研究假设，写明什么结果会推翻它。
